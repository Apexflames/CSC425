Introduction to Algorithms
Definition, Applications, NP-Complete, Linear vs Binary Search
Topic 1
1.1 What is an Algorithm?

An algorithm is a finite, step-by-step set of well-defined instructions used to solve a problem or accomplish a task. It takes an input, processes it, and produces an output.

🗣️ Plain English
Think of an algorithm like a recipe. A recipe tells you exactly what ingredients to use and what steps to follow to make a dish. An algorithm does the same thing for a computer — it's the exact steps the computer must follow to solve a problem.

Key properties every algorithm must have:

  • Input — it takes zero or more values as input
  • Output — it produces at least one result
  • Definiteness — every step is clearly and unambiguously defined
  • Finiteness — it must terminate (end) after a finite number of steps
  • Effectiveness — every step must be basic and doable
1.2 Algorithm is a Technology

An algorithm is considered a technology because just like hardware, it is something that can be developed, improved, patented, and used to create competitive advantages. A better algorithm can solve problems millions of times faster than a slow one — even on the same hardware.

💡 Real-Life Example
Google's search algorithm is a technology. It's the reason Google can search billions of web pages in less than a second. Two computers with the same hardware but different algorithms will perform wildly differently. That is why algorithm design is a fundamental skill in Computer Science.
1.3 Two Applications of Algorithms
  • Sorting Data: Used in databases, contact lists, grade books — arranging data in order so it can be searched quickly.
  • Routing/Navigation: GPS apps (Google Maps) use shortest-path algorithms to find the fastest route between two places.
1.4 What is an NP-Complete Problem?

A problem is NP-Complete if:

  1. It is in the class NP — meaning if someone gives you a solution, you can verify it quickly (in polynomial time).
  2. Every other NP problem can be reduced to it — it is at least as hard as every problem in NP.
⚠️ The Big Question: P = NP?
No one knows whether NP-Complete problems can be solved quickly (in polynomial time). If you prove P = NP, you'd win $1,000,000 from the Clay Mathematics Institute. Currently, the best algorithms for NP-Complete problems take exponential time, making them infeasible for large inputs.
🗣️ Plain English
Think of it this way: checking if a jigsaw puzzle is solved correctly is easy (NP-verifiable). But actually solving it from scratch (finding which piece goes where) is very hard. NP-Complete problems are like that — easy to check, but very hard to solve.

Examples of NP-Complete problems: Travelling Salesman Problem (TSP), Boolean Satisfiability (SAT), Knapsack Problem, Graph Colouring.

📌 What is Sorting?
Sorting means arranging a list of items in a specific order — either ascending (smallest to largest) or descending (largest to smallest). Sorting is one of the most fundamental operations in Computer Science because searching and many other algorithms are much faster on sorted data.
2.1 Bubble Sort

Bubble Sort repeatedly compares two neighbouring (adjacent) elements and swaps them if they are in the wrong order. The largest element "bubbles up" to its correct position with each pass.

🗣️ Plain English
Imagine you're arranging students in a line by height. You walk along the line, and every time you see a taller student standing before a shorter one, you swap them. You keep walking the line again and again until no more swaps are needed.
▼ Bubble Sort — Pseudocode (click to expand)▼
PSEUDOCODE — Bubble Sort
BubbleSort(A[n])
  for i = 1 to n-1 do
    for j = 1 to n-i do
      if A[j] > A[j+1] then
        swap A[j] and A[j+1]
      end if
    end for
  end for

How to read this: The outer loop runs n-1 times (we need at most n-1 passes). The inner loop compares adjacent pairs. After pass 1, the largest element is at the end. After pass 2, the second largest is in place. And so on.

2.2 Selection Sort

Selection Sort finds the smallest element in the unsorted part of the list and places it at the beginning. It repeatedly "selects" the minimum element.

🗣️ Plain English
You have a pile of numbered cards face down. You flip them all, find the smallest number, bring it to the front. Then from the remaining cards, find the next smallest, put it second. Keep going until all cards are in order.
▼ Selection Sort — Pseudocode (click to expand)▼
PSEUDOCODE — Selection Sort
SelectionSort(A, n)
  for k = 1 to n-1 do
    min = k
    for i = k+1 to n do
      if A[i] < A[min] then
        min = i
      end if
    end for
    swap A[k] and A[min]
  end for

Key difference from Bubble Sort: Bubble Sort swaps as it goes. Selection Sort makes one swap per pass (swapping the minimum to its correct position).

2.3 Insertion Sort

Insertion Sort builds a sorted list one element at a time. It takes each new element and inserts it into the correct position in the already-sorted part of the list.

🗣️ Plain English
Think of how you sort playing cards in your hand. You pick up cards one at a time, and each new card gets slotted into the right place among the cards you already hold. The left side of your hand is always sorted.
▼ Insertion Sort — Full Pseudocode (click to expand)▼
PSEUDOCODE — Insertion Sort
InsertionSort(A, n)
  for i = 2 to n do
    key = A[i]         // Pick the current element
    j = i - 1
    while j >= 1 and A[j] > key do
      A[j+1] = A[j]   // Shift element right
      j = j - 1
    end while
    A[j+1] = key       // Insert key in correct position
  end for

Step-by-step on [5, 2, 4, 6, 1]:

  1. i=2, key=2: Compare 2 with 5 → 5 > 2, shift 5 right → [2, 5, 4, 6, 1]
  2. i=3, key=4: Compare 4 with 5 → 5 > 4, shift. Compare 4 with 2 → stop. Insert → [2, 4, 5, 6, 1]
  3. i=4, key=6: 6 > 5, no shift → [2, 4, 5, 6, 1]
  4. i=5, key=1: Shift 6, 5, 4, 2 right. Insert 1 → [1, 2, 4, 5, 6] ✅

2.4 Merge Sort

Merge Sort uses the Divide and Conquer strategy. It splits the array in half, recursively sorts each half, then merges the two sorted halves back together.

🗣️ Plain English
Imagine you have a deck of cards to sort. You split it into two piles, sort each pile separately (by doing the same thing — splitting again and again until piles have one card), then you merge the two sorted piles into one by always picking the smaller top card.
▼ Merge Sort — Full Pseudocode (click to expand)▼
PSEUDOCODE — Merge Sort
MergeSort(A, low, high)
  if low < high then
    mid = (low + high) / 2
    MergeSort(A, low, mid)       // Sort left half
    MergeSort(A, mid+1, high)    // Sort right half
    Merge(A, low, mid, high)     // Merge both halves
  end if

Merge(A, low, mid, high)
  i = low;  j = mid+1;  k = low
  while i <= mid AND j <= high do
    if A[i] <= A[j] then
      B[k] = A[i];  i = i+1
    else
      B[k] = A[j];  j = j+1
    end if
    k = k+1
  end while
  Copy remaining elements of left or right into B
  Copy B back into A

Merge Sort runs in O(n log n) in ALL cases — best, average, and worst. The O(n²) sorts get slow very fast for large inputs. Merge Sort stays fast.
2.5 Quick Sort

Quick Sort also uses Divide and Conquer. It picks a pivot element, places it in its correct sorted position, puts all smaller elements to its left, and all larger elements to its right. Then it recursively sorts both sides.

🗣️ Plain English
You pick one person from a group and call them the "pivot." Everyone shorter stands to their left; everyone taller stands to their right. The pivot is now in exactly the right place. You then do the same thing to the left group and the right group — pick a pivot, split, repeat.
▼ Quick Sort — Full Pseudocode (click to expand)▼
PSEUDOCODE — Quick Sort
QuickSort(A, low, high)
  if low < high then
    p = Partition(A, low, high)
    QuickSort(A, low, p-1)   // Sort left of pivot
    QuickSort(A, p+1, high)  // Sort right of pivot
  end if

Partition(A, low, high)
  pivot = A[high]   // Last element as pivot
  i = low - 1
  for j = low to high-1 do
    if A[j] <= pivot then
      i = i + 1
      swap A[i] and A[j]
    end if
  end for
  swap A[i+1] and A[high]  // Place pivot in correct spot
  return i+1

Growth of Functions & Complexity Notations
Big-O · Omega · Theta · Little-o · Little-omega
Topic 3
3.1 Why Do We Need Notations?

When we analyse algorithms, we want to describe how fast they grow as the input size n gets very large. Instead of saying "this algorithm takes exactly 3n² + 5n + 2 operations," we use asymptotic notation to express the dominant behaviour and ignore constants.

🗣️ Plain English
If you earn ₦3,000,000 + ₦500 + ₦2, you'd just say "about ₦3 million." The smaller terms don't matter much. Same idea — when n is huge, only the fastest-growing term matters.
3.2 Big-O Notation — Upper Bound (Worst Case)

Big-O describes the maximum number of steps an algorithm can take. It gives us the worst-case scenario. We say f(n) = O(g(n)) if f(n) is eventually always ≤ c·g(n) for some constant c and all n ≥ n₀.

⚠️ Formal Definition
f(n) = O(g(n)) if there exist positive constants c and n₀ such that:
0 ≤ f(n) ≤ c·g(n) for all n ≥ n₀
🗣️ Plain English
Think of Big-O as a speed limit sign — it says "this algorithm will NEVER take more than this many steps." It's the ceiling.

Examples:

  • f(n) = 3n² + 5n + 2 → O(n²) (drop constants and lower-order terms)
  • f(n) = 100 → O(1) (constant time)
  • f(n) = 2n + log n → O(n)
3.3 Omega Notation (Ω) — Lower Bound (Best Case)

Omega (Ω) describes the minimum number of steps. It gives us the best-case scenario. We say f(n) = Ω(g(n)) if f(n) is eventually always ≥ c·g(n).

Formal Definition
f(n) = Ω(g(n)) if there exist positive constants c and n₀ such that:
0 ≤ c·g(n) ≤ f(n) for all n ≥ n₀
🗣️ Plain English
Omega is the floor — the algorithm will take AT LEAST this many steps. Even in the best scenario, it can't be faster than this.
3.4 Theta Notation (Θ) — Tight Bound (Average Case)

Theta (Θ) means the function is both O(g(n)) and Ω(g(n)) simultaneously — the algorithm grows at exactly that rate (within constant factors).

Formal Definition
f(n) = Θ(g(n)) if there exist positive constants c₁, c₂, and n₀ such that:
c₁·g(n) ≤ f(n) ≤ c₂·g(n) for all n ≥ n₀
🗣️ Plain English
Theta is the exact speed — sandwiched between a floor and ceiling. It's saying "the algorithm grows exactly like g(n), give or take a constant multiple."
3.5 Little-o and Little-ω
  • Little-o (o): f(n) = o(g(n)) means f grows strictly slower than g. f(n)/g(n) → 0 as n → ∞. Stronger than Big-O.
  • Little-omega (ω): f(n) = ω(g(n)) means f grows strictly faster than g. f(n)/g(n) → ∞ as n → ∞. Stronger than Omega.

3.8 Best Case vs Worst Case
💡 The Difference Explained
Best Case: The input is in the most favourable condition for the algorithm. E.g., for Bubble Sort, if the list is already sorted, it only needs one pass → O(n).

Worst Case: The input is in the least favourable condition. E.g., for Bubble Sort, if the list is in reverse order, it must do the maximum number of comparisons and swaps → O(n²).

Average Case: The expected behaviour over all possible inputs, usually calculated using probability. For most sorts, this equals the worst case.

Recurrence Relations
Substitution · Recursion Tree · Master Theorem
Topic 4
4.1 What is a Recurrence Relation?

A recurrence relation is an equation that expresses the running time of a recursive algorithm in terms of itself with a smaller input. For example, Merge Sort's running time T(n) depends on T(n/2).

🗣️ Plain English
Instead of saying "it takes exactly 500 steps," a recurrence says "it takes twice the time of half the problem, plus some extra work." We then solve that equation to find the closed-form answer.

Example: Merge Sort → T(n) = 2T(n/2) + O(n), with T(1) = O(1).

4.2 Three Methods for Solving Recurrences
  1. Substitution Method — Guess the solution and prove it by mathematical induction.
  2. Recursion Tree Method — Draw a tree of recursive calls and sum up the work at each level.
  3. Master Theorem — A formula that directly solves recurrences of the form T(n) = aT(n/b) + f(n).
4.3 Master Theorem

The Master Theorem solves recurrences of the form: T(n) = aT(n/b) + f(n)

  • a = number of sub-problems (a ≥ 1)
  • b = size reduction factor (b > 1)
  • f(n) = cost of work outside the recursive calls
CaseConditionSolutionWhat it means
Case 1f(n) = O(n^(log_b(a) - ε))T(n) = Θ(n^log_b(a))Recursion dominates — the recursive calls do most of the work
Case 2f(n) = Θ(n^log_b(a))T(n) = Θ(n^log_b(a) · log n)Both are equal — multiply by log n
Case 3f(n) = Ω(n^(log_b(a) + ε))T(n) = Θ(f(n))Non-recursive work dominates

Example 1: T(n) = 3T(n/4) + O(n)
a=3, b=4, f(n)=n. log₄(3) ≈ 0.79. Since n = n¹ and 1 > 0.79 + ε → Case 3 → T(n) = Θ(n)

Example 3: T(n) = 4T(n/2) + O(n) — a=4, b=2
log₂(4) = 2. f(n)=n. Since n < n² → Case 1 → T(n) = Θ(n²)
Question (i) from Past Paper: T(n) = 3T(n/4) + Θ(n²)
a=3, b=4, log₄(3) ≈ 0.79. f(n)=n². Since n² = Ω(n^(0.79+ε)) → Case 3 → T(n) = Θ(n²)
Question (ii) from Past Paper: T(n) = T(n/3) + T(2n/3) + cn
This is a non-standard recurrence. Use Recursion Tree method. At each level, total work = cn. The longest path has depth log₃/₂(n). → T(n) = Θ(n log n)
4.4 Recursion Tree Method

Draw the recursive calls as a tree. At each node, write the cost of work done (excluding recursive calls). Sum all levels.

▼ Recursion Tree for T(n) = 2T(n/2) + n (click to expand)▼
RECURSION TREE
Level 0:           n                    → cost: n
Level 1:       n/2    n/2               → cost: n/2 + n/2 = n
Level 2:     n/4 n/4 n/4 n/4           → cost: 4 × n/4 = n
Level 3:   n/8 ... (8 nodes)            → cost: 8 × n/8 = n
...
Level log n: 1 1 1 ... (n leaves)       → cost: n × 1 = n

Total levels = log₂(n)
Total cost = n × log₂(n) = O(n log n)

This confirms Merge Sort is O(n log n).

Topic 5
5.1 What is Divide and Conquer?

Divide and Conquer is a problem-solving strategy that breaks a large problem into smaller sub-problems of the same type, solves each sub-problem independently (often recursively), and then combines the solutions.

🗣️ Plain English
Think of a class project assigned to 30 students. Instead of one person doing everything, you divide the class into groups of 5, each group handles one part, and at the end all the parts are combined. Each group can even divide further if their part is too big.

Three steps of Divide and Conquer:

  1. Divide: Break the problem into smaller sub-problems.
  2. Conquer: Solve each sub-problem recursively.
  3. Combine: Merge the solutions of sub-problems into the final answer.
5.2 How Merge Sort Uses Divide and Conquer

6.1 Complexity Classes: P, NP, NP-Hard, NP-Complete
ClassDefinitionPlain EnglishExample
PProblems solvable in polynomial timeProblems a computer can actually solve quicklySorting, Binary Search, Shortest Path
NPProblems whose solutions can be VERIFIED in polynomial timeHard to solve, but easy to check if a given solution is correctKnapsack, Satisfiability
NP-HardAt least as hard as the hardest NP problemsExtremely hard — not even verified quicklyHalting Problem, TSP (optimisation)

💡 The Relationship
Every P problem is also in NP (if you can solve it quickly, you can verify it quickly). NP-Complete is the intersection of NP and NP-Hard. The big unsolved question: is P = NP? Most researchers believe P ≠ NP.
6.2 Binary Tree — Elements and Structure

A Binary Tree is a tree data structure where each node has at most 2 children — called the left child and right child.

Elements of a Binary Tree:

  • Root — the topmost node (no parent)
  • Node — each element in the tree; contains data + left pointer + right pointer
  • Leaf — a node with no children
  • Parent — a node that has at least one child
  • Height — the length of the longest path from root to a leaf
  • Level — distance from the root (root is level 0)

Binary Search Tree Structure

        /   \
       3     10      ← Level 1
      / \      \
     1   6      14   ← Level 2

BST Property: Left child < Parent < Right child
Search 6: Root(8) → 6 < 8, go Left → Node(3) → 6 > 3, go Right → Node(6) ✅ Found!
6.3 Searching in a BST

Compare target with current node. If target < node, go left. If target > node, go right. If equal, found!

Time Complexity of BST Search
Best/Average: O(log n) for a balanced BST. Worst case: O(n) if the tree is unbalanced (degenerates into a linked list).
6.4 Insertion in a BST

Search for the correct empty position (following BST property), then insert the new node there.

▼ BST Insertion Example (click to expand)▼

Insert 5 into the BST above (root = 8):

  1. 5 < 8 → go left to node 3
  2. 5 > 3 → go right to node 6
  3. 5 < 6 → go left to node 4
  4. 5 > 4 → go right — it's empty! Insert 5 here ✅
6.5 Deletion in a BST

Three cases when deleting a node:

  1. Node is a leaf — simply remove it.
  2. Node has one child — replace the node with its child.
  3. Node has two children — find the inorder successor (smallest node in right subtree), copy its value to the current node, then delete the successor.
▼ BST Deletion Examples (click to expand)▼

Delete 1 (leaf): Node 1 has no children → just remove it.

Delete 10 (one child): Node 10 has only right child 14 → replace 10 with 14.

Delete 3 (two children): Node 3 has children 1 and 6. Inorder successor of 3 = 4 (smallest in right subtree of 3). Replace 3's value with 4, then delete node 4 from its original position.

1a. Define Algorithm. (5 marks)

An algorithm is a finite, well-defined sequence of instructions or steps designed to solve a specific problem or accomplish a task, taking one or more inputs and producing at least one output.

Key properties: Input (zero or more), Output (at least one), Definiteness (each step is clear), Finiteness (terminates), Effectiveness (each step is doable).

Example: The steps to find the maximum number in a list is an algorithm.

1b. Describe any two applications of Algorithm. (5 marks)

1. Sorting: Algorithms like Merge Sort and Quick Sort are used to arrange data in a database, contact list, or any system in ascending or descending order, making retrieval faster.

2. Shortest Path / Navigation: Dijkstra's algorithm is used in GPS navigation systems (Google Maps) to find the fastest or shortest route between two locations, considering distance and traffic.

1c. Algorithm is a technology. Explain. (5 marks)

An algorithm is a technology because, like hardware, it can be designed, improved, patented, and deployed to create competitive advantages. A better algorithm can solve a problem millions of times faster on the same hardware. For example, Google's PageRank algorithm is a core technology that made Google the world's dominant search engine — not just its hardware. Algorithm design is an ongoing field of research with real economic impact.

1d. When is a problem said to be NP-Complete? (5 marks)

A problem is NP-Complete when it satisfies two conditions:
1. It is in NP: A proposed solution can be verified in polynomial time.
2. It is NP-Hard: Every problem in NP can be reduced to it in polynomial time, meaning it is at least as hard as every NP problem.

Examples: Boolean Satisfiability (SAT — first proven NP-Complete), Travelling Salesman Problem (decision version), Knapsack Problem.

The significance: if any NP-Complete problem is solvable in polynomial time, all NP problems are — this would prove P = NP.

1e. Differentiate between Linear and Binary Search. (5 marks)

Linear Search: Checks each element one by one from start to end. Does NOT require sorted data. Time complexity: O(n) worst case. Suitable for small or unsorted lists.

Binary Search: Requires sorted data. Starts at the middle; if target < middle, searches left half; if target > middle, searches right half. Repeats until found. Time complexity: O(log n) worst case.

Key difference: Binary Search is dramatically faster for large sorted datasets (1,000,000 elements: Binary takes ≤20 comparisons vs Linear's up to 1,000,000).

2a. Discuss Growth of Functions in relation to O, Ω, Θ, o, ω notations. (10 marks)

Growth of functions describes how the running time of an algorithm increases as input size n grows. We use asymptotic notations:

Big-O O(g(n)): Upper bound. f(n) ≤ c·g(n) for all n ≥ n₀. Worst-case complexity. Example: Bubble Sort = O(n²).
Omega Ω(g(n)): Lower bound. f(n) ≥ c·g(n) for all n ≥ n₀. Best-case complexity. Example: Any comparison sort = Ω(n log n).
Theta Θ(g(n)): Tight bound. c₁·g(n) ≤ f(n) ≤ c₂·g(n). Exact growth rate. Example: Merge Sort = Θ(n log n).
Little-o o(g(n)): Strictly less than g(n). f(n)/g(n) → 0 as n→∞. Example: n = o(n²).
Little-omega ω(g(n)): Strictly greater than g(n). f(n)/g(n) → ∞. Example: n² = ω(n).

2b. Differentiate between Best Case and Worst Case running time. (5 marks)

Best Case: The minimum number of operations the algorithm performs, achieved with the most favourable input. Expressed using Ω notation. Example: Bubble Sort on an already-sorted array → O(n).

Worst Case: The maximum number of operations, achieved with the least favourable input. Expressed using O notation. Example: Bubble Sort on a reverse-sorted array → O(n²).

Why worst case matters: In real systems, we must guarantee performance even in the worst scenario. A medical monitoring system cannot be "usually fast" — it must always be fast.

3a. Divide and Conquer is a concept in algorithm design that solves problems recursively. Explain. (5 marks)

Divide and Conquer is a recursive problem-solving technique with three steps:
1. Divide: Break the problem into two or more smaller sub-problems of the same type.
2. Conquer: Solve each sub-problem recursively. If the sub-problem is small enough, solve it directly (base case).
3. Combine: Merge the solutions of sub-problems to form the final answer.

Example: Merge Sort — divides the array in half, recursively sorts each half, then merges. This results in O(n log n) time rather than O(n²).

3b. State the three methods used for solving recurrences. (5 marks)

1. Substitution Method: Guess the form of the solution (e.g., "I think it's O(n log n)"), then use mathematical induction to prove that guess is correct by substituting it back into the recurrence.

2. Recursion Tree Method: Draw the recursive calls as a tree. Write the cost of non-recursive work at each node. Sum the costs across each level and across all levels to get the total.

3. Master Theorem: A direct formula for recurrences of the form T(n) = aT(n/b) + f(n). Compare f(n) to n^(log_b a) to determine which of 3 cases applies.

3c. Using recursion tree methods, solve: (i) T(n) = 3T(n/4) + Θ(n²)   (ii) T(n) = T(n/3) + T(2n/3) + cn

(i) T(n) = 3T(n/4) + Θ(n²):
Level 0: cost = n². Level 1: 3 nodes, each with cost (n/4)² = n²/16. Total = 3n²/16.
Level 2: 9 nodes, each (n/16)². Total = 9n²/256.
Geometric series ratio = 3/16 < 1, so the series converges. Root dominates → T(n) = Θ(n²).

(ii) T(n) = T(n/3) + T(2n/3) + cn:
This has unequal splits. The tree has depth log₃/₂(n) (longest branch). At each level, total work = cn.
Total = cn × log₃/₂(n) = cn × (log n / log(3/2)) = cn × O(log n) → T(n) = Θ(n log n).

4a. Write the Pseudocode for Insertion Sort Algorithm. (5 marks)

Insertion Sort Pseudocode
InsertionSort(A, n)
  for i = 2 to n do
    key = A[i]
    j = i - 1
    while j >= 1 and A[j] > key do
      A[j+1] = A[j]   // Shift element one position right
      j = j - 1
    end while
    A[j+1] = key       // Insert key in correct position
  end for

4b. Analyse step-by-step the worst case running time of Insertion Sort. (5 marks)

Worst case: Input is in reverse sorted order (e.g., [5, 4, 3, 2, 1]).

For iteration i=2: key=A[2], inner while runs 1 time.
For iteration i=3: inner while runs 2 times.
For iteration i=k: inner while runs k-1 times.
For iteration i=n: inner while runs n-1 times.

Total comparisons = 1 + 2 + 3 + ... + (n-1) = n(n-1)/2 = Θ(n²).
Therefore, worst case running time = O(n²).

4c. State the Best and Average Case of Insertion Sort. (5 marks)

Best Case — O(n): Input is already sorted. The inner while loop never executes (A[j] ≤ key always). Only the outer for loop runs n-1 times → linear time.

Average Case — O(n²): For a random permutation, on average each element is compared with half the sorted sub-array before insertion. Total comparisons ≈ n²/4 = Θ(n²).

Note: Despite O(n²), Insertion Sort is fast for small arrays (n ≤ 15) and is used as a subroutine in hybrid sorts like Timsort.

5a. Describe Merge Sort in relation to Divide and Conquer. (5 marks)

Merge Sort is a classic implementation of Divide and Conquer:
Divide: Split array A[low..high] at midpoint mid = (low+high)/2 into A[low..mid] and A[mid+1..high].
Conquer: Recursively call MergeSort on each half. Base case: array of size 1 is trivially sorted.
Combine: Merge the two sorted halves. Compare elements from each half one by one, always taking the smaller → produces a fully sorted array.

The Merge step does Θ(n) work. There are Θ(log n) levels of recursion. Total: Θ(n log n).

5b. Using MergeSort Function, write the pseudocode for sorting the divided arrays. (5 marks)

MergeSort + Merge Pseudocode
MergeSort(A, low, high)
  if low < high then
    mid = (low + high) / 2
    MergeSort(A, low, mid)
    MergeSort(A, mid+1, high)
    Merge(A, low, mid, high)
  end if

Merge(A, low, mid, high)
  i = low;  j = mid+1;  k = low
  while i <= mid AND j <= high do
    if A[i] <= A[j] then
      B[k] = A[i];  i++
    else
      B[k] = A[j];  j++
    end if
    k++
  end while
  while i <= mid do B[k++] = A[i++] end while
  while j <= high do B[k++] = A[j++] end while
  for m = low to high do A[m] = B[m] end for

5c. Explain how Quicksort is different from Merge Sort. (5 marks)

Pivot vs No Pivot: Quick Sort selects a pivot and partitions the array around it. Merge Sort has no pivot — it splits at the midpoint.

Combine step: Quick Sort does all the work in the Divide step (partitioning). Merge Sort does the work in the Combine step (merging). Quick Sort's combine step is trivial.

Space: Quick Sort is in-place (O(log n) stack). Merge Sort needs O(n) extra memory for the temp array.

Worst Case: Quick Sort = O(n²) if the pivot is always the min/max. Merge Sort = always O(n log n).

Stability: Merge Sort is stable; Quick Sort is not.

6a. Describe the elements of a Binary Tree (with diagram). (5 marks)

A Binary Tree is a hierarchical data structure where each node has at most 2 children (left and right).

Elements: Root (topmost node, no parent), Node (contains data + two child pointers), Leaf (node with no children), Parent, Sibling (nodes sharing a parent), Height (longest root-to-leaf path), Depth (distance from root).

Binary Search Tree Diagram
         50          ← Root
        /  \
      30    70        ← Internal Nodes
     /  \   / \
   20   40 60  80    ← Leaves (no children)

BST Rule: Left subtree values < Root < Right subtree values

6b. Using an example, show how Searching, Insertion and Deletion are performed in a BST. (6 marks)

Using BST with root 50 as above:

Search for 40: 40 < 50 → go left (30) → 40 > 30 → go right (40) → Found! O(log n).

Insert 35: 35 < 50 → left (30) → 35 > 30 → right (40) → 35 < 40 → left (empty) → Insert 35 as left child of 40.

Delete 30 (two children): Find inorder successor = smallest in right subtree of 30 = 35. Replace 30's value with 35. Delete node 35 from its original position. Result: 35 takes 30's place with children 20 and 40.

What is the difference between P, NP, NP-Hard, and NP-Complete problems? Give one example of each.
🔮 LIKELY QUESTION 📍 See Topic 6.1 — Complexity Classes
P (Polynomial): Problems that can be SOLVED in polynomial time. Example: Sorting (O(n log n)), Binary Search O(log n).

NP (Non-deterministic Polynomial): Problems whose solutions can be VERIFIED in polynomial time. Example: Integer factorisation — given a factorisation, checking it is easy; finding it is hard.

NP-Hard: Problems as hard as any NP problem, but not necessarily in NP (cannot even be verified quickly). Example: Halting Problem (undecidable), TSP optimisation version.

NP-Complete: Problems that are BOTH in NP and NP-Hard. Example: Boolean SAT (Cook-Levin theorem, 1971), TSP decision version, Graph Colouring.

Relationship: P ⊆ NP. NP-Complete = NP ∩ NP-Hard. If P = NP (unproven), all NP problems could be solved efficiently.

Define and prove that f(n) = 2n² + 3n + 1 is O(n²). Also state if it is Θ(n²).
🔮 LIKELY QUESTION 📍 See Topic 3.2 — Big-O definition & proof
Prove f(n) = 2n² + 3n + 1 is O(n²):
We need to find constants c and n₀ such that 2n² + 3n + 1 ≤ c·n² for all n ≥ n₀.

For n ≥ 1: 3n ≤ 3n² and 1 ≤ n².
So: 2n² + 3n + 1 ≤ 2n² + 3n² + n² = 6n².
Choose c = 6 and n₀ = 1. Then 2n² + 3n + 1 ≤ 6n² for all n ≥ 1. ✅
Therefore f(n) = O(n²).

Is it Θ(n²)? Yes. Also need to show 2n² + 3n + 1 ≥ c·n² for some c.
Clearly 2n² + 3n + 1 ≥ 2n² for all n ≥ 1. Choose c₁ = 2.
So f(n) = Ω(n²). Since f(n) = O(n²) AND f(n) = Ω(n²) → f(n) = Θ(n²). ✅

Explain what a stable sorting algorithm is. Which of the five sorting algorithms (Bubble, Selection, Insertion, Merge, Quick) are stable? Justify your answer.
🔮 LIKELY QUESTION 📍 See Topic 2.6 — Sorting Comparison Table
A stable sorting algorithm preserves the relative order of elements with equal keys. If two records have the same value and record A appears before record B in the original array, A must also appear before B in the sorted result.

Why it matters: If you sort students by score, a stable sort keeps students with equal scores in their original registration order.

Stable sorts: Bubble Sort ✅ (adjacent swaps never change equal elements' order), Insertion Sort ✅ (shifts right, never swaps equal elements past each other), Merge Sort ✅ (during merge, left element is preferred when equal).

Unstable sorts: Selection Sort ❌ (the long-range swap can disrupt equal elements), Quick Sort ❌ (partitioning can move equal elements past each other).

What is the Travelling Salesman Problem (TSP)? Why is it considered NP-Complete? How does the Brute Force approach solve it and what is its complexity?
🔮 LIKELY QUESTION 📍 See Topic 1.4 & Topic 6.1 — NP-Complete
TSP (Travelling Salesman Problem): Given a list of n cities and distances between each pair, find the shortest possible route that visits every city exactly once and returns to the starting city.

Why NP-Complete: (1) It's in NP — given a proposed route, we can verify its total distance in O(n) time. (2) It's NP-Hard — it can be reduced from other NP-Complete problems (Hamiltonian Cycle). It is NP-Complete in its decision form ("Is there a tour shorter than k?").

Brute Force solution: Try all possible orderings (permutations) of n cities. Number of routes = (n-1)!/2. For n=10: 181,440 routes. For n=20: 60 trillion routes.

Complexity: O(n!) — factorial time. Completely impractical for large n. This is why real-world GPS uses approximate heuristic algorithms.
